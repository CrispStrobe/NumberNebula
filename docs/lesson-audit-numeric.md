# Numeric puzzle lesson and hint audit

This audit covers 16 registered games. Each new English/German lesson in `lib/features/games/models/lessons_numeric.dart` explains the actual goal and a legal input, presents a visible board or board fragment, asks the learner to apply the mechanic, and explains the plausible incorrect choices. The new guidance is in `lib/features/games/services/numeric_hint_guidance.dart`.

The examples are teaching fixtures, not claims about generated difficulty, shortest solutions, or child playtest results. A board fragment describes only its stated constraints. This source audit does not establish that the interface is usable on a device. It does not replace remote compilation, focused hint tests, or browser verification.

## Live hint decisions

The helper reads snapshots and visible equations/current placements only. It never reads `solution`, `fullSolution`, `_fullSolution`, `secretCode`, unknown answer keys, or generated correct-time fields.

For the six retained constraint-solver branches, the wrapper supplies `_hintVerified`, `_hintTarget`, `_hintValue` from the existing `BoardHint`. These metadata describe the same move already checked by the bounded solver. The helper explains that same move with concrete current lines/rows/cages and preserves the distinction between a supported completion and a forced deduction. It does not claim a partial shown row proves a globally constrained value.

## Remaining issues and validation scope

- Arithmetic Square's live board may present mixed operations without grouping even though the evaluator is sequential. This audit makes lesson/hint grouping explicit; the live renderer must also clearly show the operation order. Teaching `(2+3)×4=20` is valid; presenting unparenthesized `2+3×4=20` as ordinary arithmetic is not. Retain the working evaluator, and group its displayed expression or provide an explicit sequential mode.
- Cryptex's current `_calculateLeftSide` uses absolute subtraction and truncating integer division, although ordinary minus/division glyphs can suggest conventional arithmetic. The new helper discloses the actual rule when relevant and the lesson's checked example uses only ordinary exact addition/multiplication. A separate renderer/rules repair should display absolute differences and whole-number quotients explicitly, preserving a selectable legacy path if calculation semantics are changed. Do not teach a truncated quotient as an ordinary exact equality.
- A bounded solver finding one completion does not prove that every wrong placement is identified or that the suggested value is logically forced. Timeout remains “no compatible completion found within the limit,” not “unsolvable.”
- Static exercises do not establish calibrated felt difficulty or learning effectiveness. Difficulty requires operation/constraint/sample comparisons and eventually child playtests; no such outcomes are claimed here.
- No local build, analyzer, full test suite, browser run, or solver stress job was executed for this audit. Root integration must verify every lesson's unique correct option, actual state-schema guidance, and the wrapper's proof metadata on the remote runner.

The dedicated Star Forge, Orbital Towers and Number Walls hint buttons also use
the audited numeric guidance. Their asynchronous completion searches, round
identity checks and demonstration callbacks remain intact; explanations are
attached to the exact move from that search, rather than running another solver.
